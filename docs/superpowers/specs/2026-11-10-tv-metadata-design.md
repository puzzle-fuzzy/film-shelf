# 电视剧与豆瓣资料接入设计

日期：2026-11-10。状态：待用户确认，尚未进入产品代码实现。

## 目标与已验证依据

让 Film Shelf 能搜索、确认并收录整部电视剧，保存一张本地主封面、首播日期、简介、演员姓名和集数。沿用现有推荐 / 已观影、磁力链接、首页片架和详情流程。

当前已经实测豆瓣匿名搜索与详情接口：《我的大叔》（2018，韩国，豆瓣 ID 27602137）可返回首播日期 2018-03-21、16 集、简介、19 名演员和 1048×1500 的 JPEG 封面。这里只将结果作为接入样例，不自动把它写入用户片库。TMDB 官方也支持电视剧搜索、详情、图片与全剧演员；仓库目前仅接入电影路径。

## 接入方案与取舍

1. 在后端运行原版 douban-cli：可以快速获得 JSON，但详情输出缺封面、演员只有姓名，而且服务运行会依赖额外 CLI 进程。
2. **建议采用：扩展现有 TMDB provider，同时增加 Bun / TypeScript 豆瓣 provider。** 使用当前已核实的豆瓣公开查询方式，直接保留高清封面。所有外部请求均在服务端执行，不读取浏览器 Cookie，不引入登录功能或 CLI 运行依赖。
3. 只扩展 TMDB 电视剧：改动较少，但不能满足本次已验证的豆瓣资料来源需求。

这是依据前面对话提出的具体实现建议；双来源并不表示自动把两个网站的结果合并成一条资料。

## 首版范围

- 收录单位是选中来源中的一个影视条目，主封面一张；电影与电视剧都可选择 TMDB 或豆瓣搜索并导入。首版不拆分单集。
- **来源粒度是本设计建议：** TMDB 的整剧条目可以独立收录；豆瓣若按季建条目，也允许逐季独立收录，保留来源标题与 ID，不自动把多季聚合成一部剧。集数与“已观影”均对应所选条目，不推断整系列完成。导入界面提示“按所选资料源条目收录”，便于用户核对季别。
- 用户在候选中核对片名、年份、国家（来源有返回时）和封面，明确点击导入。名称相同不能视为同一作品。
- 演员信息按来源能力展示。TMDB 保留人物 ID、角色和照片；豆瓣首版保留姓名，没有可靠人物标识时不显示演员跳转。
- 提供电影 / 电视剧筛选和类型标记，首播日期与电影上映日期使用正确措辞，电视剧有集数时展示。
- 首版不增加分季分集观看进度、多海报管理、豆瓣演员作品页或跨网站自动匹配。缺少部分资料时使用现有空值和占位表现。

## 数据模型与迁移

保留 `movies` 表名与本地自增 `id`，使已有 `/movies/:id` 链接保持有效。新增字段：

- `mediaType`：`movie | tv`，数据库非空，默认 `movie`；旧记录自动属于电影。
- `doubanId`：可空正整数，独立唯一索引。
- `episodeCount`：可空正整数，仅电视剧使用。

保留 `tmdbId`，将现有单列唯一索引替换为 `(mediaType, tmdbId)` 唯一索引，允许 TMDB 电影与电视剧恰好使用相同数字 ID。豆瓣导入只写豆瓣 ID，TMDB 导入只写 TMDB ID；不把豆瓣 ID 填进 TMDB 字段。

迁移采用新增列、删除旧独立索引、创建新索引，不重建或清空电影表。必须保留全部已有字段、搜索列、观影排序、时间和本地海报引用，验证关闭重开与重复迁移。

同一来源、同一类型与同一外部 ID 重复导入返回 409。首版不按标题自动关联不同来源，因此从两个来源分别导入同一作品可能产生两条记录；界面保留来源和外部详情链接供核对，不提供静默覆盖或自动合并。已有无外部 ID 的手动记录仍正常使用。

## Provider 与 API

共享契约新增媒体类型与来源类型 `tmdb | douban`，新增来源中立的候选结构：来源、媒体类型、外部 ID、片名、原名、年份、可选国家、封面、日期和简介。导入详情在服务端重新获取，不能直接信任浏览器提交的完整候选资料。

- 新增 `GET /api/metadata/search?provider=douban&mediaType=tv&q=我的大叔`，返回来源中立候选。`provider` 和 `mediaType` 必须校验，未知值返回 400。
- 扩展现有 `POST /api/movies/import`，接受 `{ provider, mediaType, externalId, magnetUrl? }`；继续接受旧 `{ tmdbId, magnetUrl? }`，其语义固定为 TMDB 电影。
- 保留 `/api/tmdb/search` 和 `/api/catalog/movies/:tmdbId` 的既有电影语义；新电视剧只读详情使用带类型的路径，避免同号混淆。
- `/api/movies` 可选 `mediaType` 筛选；不传时返回全部作品。列表分页、状态计数和首页海报 preload 使用相同的媒体筛选，计数仍不随名称搜索缩小。网格及完整详情响应增加媒体类型，完整详情包含豆瓣 ID 与集数。
- `/api/health` 保留 `tmdbConfigured`，新增可用资料源说明；没有 TMDB Token 时豆瓣仍可单独工作。

TMDB 的电视剧字段映射 `name → title`、`original_name → originalTitle`、`first_air_date → releaseDate`、`number_of_episodes → episodeCount`。全剧演员读取 `aggregate_credits`，合并同一人的角色；详情及演员作品缓存键必须包含媒体类型。中文简介缺失时允许请求英文补充，保留空值处理。

豆瓣搜索区分 `movie` / `tv`，保留年份和国家帮助核对。详情选择 API 实际返回的高清 `cover.image.large.url`，回退到可用的主封面字段；不通过替换图片路径猜测高清地址。`pubdate` 只提取并校验完整日历日期，选取有效日期中最早的一项；只有年份或未知日期时使用 null，不能补造月日。演员映射为姓名、空角色和空照片，不填 `tmdbPersonId`。兼容缺失集数、封面和简介；结构异常、超时、限流或验证页必须返回明确错误，不伪装成空结果。

豆瓣请求仅使用固定站点与固定资源路径，设置超时和有限请求并发；成功详情使用有上限的短期缓存并合并并发请求，不缓存失败。遇到限流或安全验证时停止，不设计绕过流程。

## 图片保存

保留已有 `/api/posters/...` 文件格式、文件检查、大小限制、并发去重和缩略图逻辑。增加豆瓣图片来源解析，只允许经过严格验证的 HTTPS 豆瓣图片域与已验证照片路径，重定向后的目标也必须验证，不能退化为接受任意 URL。

搜索预览仍按需获取，避免搜索时下载全部封面；豆瓣高清主封面在导入落库前完成本地保存。候选的小尺寸签名图片只用于预览，不作为唯一持久化来源。前端继续只使用本站图片地址；缓存后无需实时连接豆瓣也能浏览已有封面。

## 管理端与展示端

沿用当前 shadcn 管理界面与展示端 CSS，不做视觉重设计。

- 添加弹窗增加“电影 / 电视剧”和“TMDB / 豆瓣”选择。默认保持电影 + TMDB；没有 Token 时默认可用的豆瓣来源。切换来源或类型会取消旧搜索、清空旧候选，避免错导入。
- 候选展示来源、类型、年份和国家（有值时）；状态和 React key 使用来源 + 类型 + 外部 ID，不能只用数字 ID。导入期间保持本次来源、类型和候选一致。
- 管理表格增加简洁类型标记与筛选，仍使用单张表格。保留现有名称搜索、分页、状态更新和磁力编辑。
- 展示首页的两个片架继续存在，增加统一媒体筛选并保存在 URL；切换筛选重置两个片架页码，详情返回保留原筛选与页码。
- 详情共用原组件，电视剧展示“首播”和可用集数；错误及空态措辞适用于电影和剧集。
- TMDB 演员页可以切换参演电影 / 电视剧，URL 保存类型；从电视剧详情进入时默认电视剧。未收录作品跳到带媒体类型的只读详情。演员作品与本地片库状态叠加也必须按媒体类型和 ID 匹配。
- 豆瓣演员姓名不生成 TMDB 链接；不自动用姓名猜测人物 ID。

## 验收与验证边界

自动化验证使用真实临时 SQLite 和模拟外部响应，不写个人片库、不依赖真实 Token 或外网稳定性。必须覆盖：

1. 旧电影迁移后所有字段、ID、观影顺序及链接不变；同号 TMDB 电影与电视剧可以并存，重复导入仍被拦截。
2. TMDB 电影旧 API、演员作品与缓存行为保持兼容，电视剧字段、全剧演员角色、只读详情及片库状态正确。
3. 豆瓣《我的大叔》样例的日期、16 集、演员姓名和高清封面映射正确；搜索候选能区分同名韩剧与日剧，导入严格使用选中的外部 ID，来源类型不一致时拒绝导入。
4. 新来源图片能本地保存并离线读取，任意域名、路径穿越、非法重定向、伪图片与超限响应被拒绝。
5. 无 TMDB Token 时仍可搜索豆瓣；旧请求被取消、快速切换来源或类型不会导入旧候选；上游错误与缺失字段有可理解的表现。

运行项目 typecheck、完整 Bun 测试、两个前端 build，并进行管理端导入与展示端详情 / 返回导航的界面核验。真实豆瓣仅做少量只读查询和图片下载验证；除非用户明确要求，不自动导入《我的大叔》或其他示例作品。
