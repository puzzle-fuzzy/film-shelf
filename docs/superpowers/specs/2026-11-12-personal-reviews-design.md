# 个人观后感

用户已确认：在管理端编辑观后感，现有 `MovieDiary/diary.txt` 一次性导入；日记中的《八仙》对应现有《八仙！》（2026，片库 ID 9）。本设计记录当前对话中已确认的方案。

## 目标与范围

- 在现有影片详情的简介下方展示「我的观后感」，保留原文、标点和换行；空内容不显示区块。
- 管理端沿用现有影片详情抽屉，增加纯文本输入框和保存按钮，支持修改和清空。
- 观后感与影片一起存入 SQLite；电影和电视剧均可维护，不依赖当前想看/已观影状态。
- 一次性导入 26 个日记条目中有正文的 23 条；另外 3 条保持为空，不修改原始文件。
- 保留现有影片 ID、简介、演员、图片、磁力、观影日期及排序。

## 方案

1. **管理端维护（用户已选择）**：首次导入原文，之后通过管理端或现有私有 API 更新。数据来源统一，适合当前个人片库。
2. 继续维护文本文件再同步：可沿用写作方式，但需要每次确认同步及覆盖关系。用户未选择此方案。

不增加评分、公开评论、富文本编辑器、自动文件监听或新的管理菜单。

## 数据与接口

- `movies.personal_review TEXT NULL`，共享 `Movie.personalReview: string | null`。
- `PATCH /api/movies/:id/personal-review`，请求 `{ personalReview: string | null }`，返回 `{ movie: Movie }`。
- 正文上限 20000 字符；非空正文原样保存。空字符串、纯空白或 null 清空为 null。相同内容保存不更新时间。
- 普通影片详情与四个来源详情路径返回本地观后感；未收录的来源条目返回 null。
- 首页网格及演员片单继续使用精简投影，不携带观后感长文本。
- 新增列采取追加迁移；不把个人观后感加入 TMDB/豆瓣元数据输入契约。

## 展示与维护

区块位于简介下、磁力及演员上，沿用详情页分隔线、标题和正文样式。正文通过 React 文本节点展示，保留换行。管理端输入与保存反馈沿用已有磁力编辑模式。

## 验证与交付

API 验证保存、覆盖、清空、原文往返、无变化保存、非法输入、来源详情和数据库升级/重开。检查网格不携带正文，旧记录完整保留。执行 Bun 测试、类型检查和前后端构建，独立审查差异；用隔离 QA 数据验证管理端保存及移动/桌面展示。线上升级前备份数据库并在克隆库试迁移，沿用当前发布目录和只读公网入口；通过私有 API 导入 23 条并逐字回读，核对原有数据和观影顺序。
